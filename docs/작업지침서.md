# SRM 프로토타입 작업지침서 (Claude / GPT / Gemini 공용)

이 문서는 이 프로젝트를 어떤 AI 도구가 이어받아 작업하더라도 동일한 결과물이 나오도록 만든 실행 지침입니다.
작업을 시작하기 전에 반드시 순서대로 읽으십시오.

## 1. 읽는 순서
1. 이 문서(작업지침서.md)
2. `작업진행현황.md` — 지금 어디까지 됐는지, 다음에 뭘 해야 하는지
3. `../DESIGN_GUIDE.md` — 색상/타이포/레이아웃/컴포넌트 규격 (전체 1,111줄, 목차는 문서 상단 참고)
4. `[참고] 메뉴구조도 및 기능명세서.xlsx` — 메뉴 트리, 화면별 기능 설명
5. `SCREEN_LIST.md` — 이번에 작업할 화면이 어느 PPTX 몇 번 슬라이드인지
6. 해당 `[참고] 화면설계(...).pptx` 파일의 해당 슬라이드

## 2. 절대 규칙
1. **화면설계(PPTX)에 그려진 화면 구성·배치·항목·라벨·문구·표 컬럼·버튼 종류·팝업 구조를 추론하거나 임의로 바꾸지 않는다.** PPTX에 있는 그대로 옮긴다. 애매하거나 잘려 보여도 지어내지 말고, 보이는 그대로 + 옆의 주석(설명 텍스트박스)을 근거로 판단한다.
2. **색상·폰트·간격·헤더/사이드바/푸터/버튼/배지 등 "공통 UI 부품의 생김새"는 `DESIGN_GUIDE.md`를 따른다.** PPTX 와이어프레임은 손그림 수준의 사각형/텍스트로만 되어 있으므로 실제 색이나 폰트를 지정하지 않는다 — 이 부분은 디자인 가이드가 기준이다.
3. 두 문서가 정말 충돌하는 경우(예: PPTX에 없는 브레드크럼을 가이드가 요구하는 경우)는 **가이드의 공통 규칙(헤더/사이드바/브레드크럼/푸터/타이틀 영역)이 우선**, 그 외 본문 콘텐츠는 **PPTX가 우선**.
4. 업무 로직·유효성 검증·서버 연동은 만들지 않는다(디자인 가이드 0장 참고). 탭 전환, 모달 열고 닫기, 스텝 이동, 아코디언 펼침 등 "디자인을 보여주기 위한" 수준의 인터랙션을 구현한다. 사용자 요청(2026-09-24)에 따라 Description의 조건부 표시·허용 선택지·입력 활성화·필수 표시·완료 조회 상태도 반드시 포함한다(디자인 가이드 5.7.1).
5. 화면 하나를 완성하면 반드시 `작업진행현황.md`와 `SCREEN_LIST.md`의 상태 칸을 갱신한다. 갱신하지 않으면 다음 작업자(다른 AI 포함)가 중복 작업하거나 진행 상황을 오판한다.

사용자가 화면 오류를 지적하면 해당 화면뿐 아니라 프로젝트 내 같은 패턴의 오류를 함께 검색·수정한다. 완료·조회 상태에서는 파일 첨부/찾아보기/드래그 업로드/삭제 컨트롤을 노출하지 않으며, 파일명과 조회·다운로드만 유지한다. 작성·수정 상태의 첨부 기능은 유지한다. 완료·조회 팝업의 종료 버튼은 `닫기`, 작성·수정 및 처리 전 확인 팝업은 `취소`로 표시한다.

검색·조회 목록의 링크는 번호에 일괄 부여하지 않는다. 원본 표의 링크 서식과 Description을 대조하여 번호/건명/업체명 각각의 문서 팝업·업무 상세 목적지를 구분한다. 예시 행 생성 코드도 원본의 링크 열과 목적지를 보존해야 한다. 상세 규칙은 `NAVIGATION_AUDIT.md` 참조.

## 3. PPTX 슬라이드를 읽는 방법
- PPTX는 스크린샷이 아니라 **네이티브 도형(사각형/선/원/표/텍스트박스)으로 그려진 와이어프레임**이다. 즉 도형의 좌표·크기·텍스트를 그대로 신뢰할 수 있다.
- 슬라이드를 이미지로 캡처해서 눈으로 배치를 확인하거나, `python-pptx`로 도형 목록(이름/좌표/텍스트)을 덤프해서 구조를 파악한다.
- 각 슬라이드 좌측 상단에는 보통 `1Depth > 2Depth > 3Depth` 형태의 브레드크럼 텍스트박스가 있고, 화면 우측이나 하단에는 별색 텍스트박스로 **설계 의도 설명(주석)**이 붙어 있는 경우가 많다 — 이 주석은 화면에 그대로 넣는 문구가 아니라 "왜 이렇게 만들었는지"에 대한 참고 설명이므로 화면 자체에는 반영하지 않는다(단, 버튼 클릭 시 상태 변화 등 동작 설명은 인터랙션 구현에 참고).
- 좌측 사이드바 메뉴 목록이 매 슬라이드에 반복해서 그려져 있는데, 이는 참고용이며 실제 사이드바는 기존 8개 기준 화면(예: `SRMDetail.html`, `SRMDashboardAdmin.html`)의 사이드바 블록을 그대로 복사해서 재사용한다. 슬라이드마다 사이드바를 새로 그리지 않는다.
- 슬라이드 위에 찍힌 원형 숫자(①②③ 등, 도형이름 "타원")는 UI 요소가 아니라 **우측 여백 설명 텍스트박스의 항목을 가리키는 각주 마커**다. 실제로는 그 위치의 입력요소(select 옵션 값, 버튼 등)를 설명 텍스트 내용대로 구현하면 되고, 원형 숫자 자체는 화면에 그리지 않는다.
- **표준 컴포넌트의 필수 요소(예: DESIGN_GUIDE 5.2의 검색/초기화 버튼을 별도 액션 행에 배치)가 와이어프레임에 없거나 다르게 그려진 경우, 그 요소가 "공통 UI 부품의 동작 방식"에 해당하면 DESIGN_GUIDE를 따른다.** (예: PPTX에 초기화 버튼이 없고 검색 버튼이 입력 필드와 같은 줄에 있어도, 실제 구현은 가이드 표준대로 검색+초기화를 필드 아래 독립 액션 행에 둔다.) 반면 필터 항목의 종류·라벨·옵션값 자체는 PPTX 그대로 따른다.

## 4. 슬라이드 ↔ HTML 파일 매핑 규칙
- 기본 단위는 **브레드크럼의 마지막 마디(화면명)** 다.
- 같은 화면명 아래 여러 슬라이드가 있는 경우(검색화면 + 상세정보, 또는 상세정보의 탭 여러 개)는 **DESIGN_GUIDE 6장의 화면 패턴**에 맞춰 판단한다:
  - "검색/조회 → 상세정보"는 보통 두 개의 HTML(목록/상세)로 분리.
  - 상세정보 안에서 `발주계획 정보 / 체크리스트 / 품목정보 / 전자결재`처럼 나열된 것은 **탭**(업무 탐색 탭, 5.7)으로 한 HTML 안에 구현.
  - `(팝업)`, `추가하기`, `처리하기`, `선택` 등 괄호·동사형 타이틀이 붙은 슬라이드는 **모달 팝업**으로 부모 화면의 `</body>` 직전에 구현.
  - 신청/등록처럼 `Step#1~5` 또는 "기본정보→체크리스트→품목→확인→완료"식 순차 슬라이드는 **위저드(단계형)** 패턴으로 구현.
- 애매하면 SCREEN_LIST.md에 그룹핑 결과를 각주로 남기고 다음 작업자가 알 수 있게 한다.

- `modules` 아래 폴더는 화면설계 PPTX 파일 번호·이름과 1:1로 대응한다. 새 모듈 작업을 시작하기 전에 해당 폴더가 없으면 먼저 만든다.
- **공통 자산 경로 규칙**: 모듈 화면은 루트 기준 2단계 하위에 있으므로 스타일·스크립트·이미지에 `../../assets/...` 경로를 사용한다.
- **화면 간 링크 경로 규칙**: 같은 폴더(같은 모듈) 안의 다른 화면은 파일명만 쓰고(`href="SRMIpManage.html"`), 다른 폴더(다른 모듈)의 화면은 `../폴더명/파일명.html` 형식으로 쓴다(`href="../03_대시보드/SRMDashboardAdmin.html"`).
- 루트 `index.html`은 PMS/SRM을 고르는 초기화면(런처)이다. PMS 카드는 별도 배포된 PMS 프로토타입(외부 URL)으로, SRM 카드는 `modules/01_협력업체창구_로그인전/SRMLogin.html`로 연결된다.
- SRM의 실제 진입점은 `modules/01_협력업체창구_로그인전/SRMLogin.html`(로그인 화면)이다. 로그인 아이디 `1`은 협력업체 대시보드(`02_협력업체창구_로그인후/SRMDashboardPartner.html`), `2`는 내부 관리자 대시보드(`03_대시보드/SRMDashboardAdmin.html`)로 이동한다.
- 초기화면은 업무 화면이 아니므로 공통 헤더·사이드바를 두지 않으며, 업무 화면의 사이드바·브레드크럼에서 `index.html`로 연결하지 않는다(로그아웃 등 로그인 화면으로 돌아가는 링크는 `SRMLogin.html`을 가리킨다).
- 파일명은 기존 8개 기준 화면과 같은 규칙(파스칼케이스, 화면 성격을 드러내는 이름)을 따른다. 예: `SRMNoticeSearch.html`, `SRMNoticeDetail.html` 등. 최종 파일명·소속 폴더는 각 Phase 작업 시 정하고 `SCREEN_LIST.md`에 폴더까지 포함해 기록한다.

## 6. 화면 간 연결(네비게이션) 원칙
- **작업 순서는 화면설계 PPTX 파일 번호(00→01→02→03→04→05→06→07-1→07-2→08→09→10) 순서 그대로 진행한다.** 업무 재사용 효율이 아니라 사용자 검토 편의가 기준이다.
- 목표는 클릭 한 번씩으로 로그인부터 화면설계 순서를 따라 끝까지 넘어갈 수 있는 "이어붙이기형" 프로토타입이다. 업무 로직(저장/검증/서버 처리, 실제 데이터 계산)은 만들지 않는다 — 화면 연결과 Description의 조건부 화면 상태까지 구현한다. 상세 범위와 원문 불일치는 `CONDITIONAL_UI_AUDIT.md`를 참고한다.
- 화면을 하나 완성할 때마다:
  1. 그 화면 안에서 이미 만들어진 다른 화면으로 가는 링크(사이드바 메뉴, 목록→상세, 상세→목록, 탭, 팝업 열기/닫기, 단계 이동 버튼, "다음/이전/목록/등록" 등)를 실제 파일명으로 연결한다.
  2. 아직 만들어지지 않은 대상은 `href="#"`로 남겨둔다.
  3. **그 대상 화면을 나중에 만들 때, 이전에 만들어 둔 화면으로 돌아가 `href="#"`였던 링크를 실제 파일명으로 교체한다.** (역방향 연결 보완 — 이 작업을 잊지 않도록 `SCREEN_LIST.md`의 해당 행에 "◀연결필요: 파일명" 형태로 메모해 둔다.)
- 사이드바는 모든 화면에서 동일해야 하므로(4.2), 사이드바의 링크 갱신은 이미 만든 화면 전체에 일괄 반영한다.

## 7. 화면 하나 작업하는 표준 절차
1. `작업진행현황.md`에서 다음 Phase/모듈 확인 (PPTX 파일 번호 순서)
2. `SCREEN_LIST.md`에서 해당 모듈의 슬라이드 범위·브레드크럼 확인
3. 해당 PPTX의 슬라이드를 도형 덤프(+필요 시 스크린샷)로 확인
4. `DESIGN_GUIDE.md` "새 화면 만들기" 절차(문서 최상단)대로 화면 유형 결정 → 기준 화면에서 헤더/사이드바/푸터 복사 → 본문만 신규 작성
5. 6장 원칙대로 이미 만들어진 화면과 실제 링크로 연결하고, 이 화면으로 들어오는 링크가 걸려있던(이전에 `#`로 남겨뒀던) 기존 화면들도 찾아서 실제 파일명으로 교체
6. 완성 후 1920/1440/1280px 및 DESIGN_GUIDE 8장 체크리스트로 자체 점검
7. `SCREEN_LIST.md`의 해당 행 상태를 `☑ 완료`로, `작업진행현황.md`의 Phase 진행수를 갱신
8. 애매한 판단(그룹핑, 문구 해석 등)이 있었다면 간단히 메모로 남긴다

## 8. 도구 간 인계 시 유의사항
- 이 저장소에는 특정 AI 전용 기능(예: Claude Artifact)을 사용하지 않는다. 모든 결과물은 **일반 파일(HTML/CSS/JS/MD)**로 저장한다 — 어떤 도구든 열어서 이어 작업 가능해야 한다.
- 세션을 마칠 때는 반드시 진행 상황 파일 두 개(`작업진행현황.md`, `SCREEN_LIST.md`)를 최신 상태로 남긴다.
