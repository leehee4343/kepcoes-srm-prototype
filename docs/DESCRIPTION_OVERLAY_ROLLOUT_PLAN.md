# 화면설계 Description 개발자 가이드 전수 적용 계획

> 작성일: 2026-09-22  
> 기준 규격: `DESIGN_GUIDE.md` v2.33, 5.15  
> 기준 구현: `modules/00_공통관리/SRMAdminManage.html`

## 1. 목표

본 프로젝트의 모든 실행 화면에서 원본 화면설계 PPTX의 Description과 붉은 번호 목적지를 구현 화면 위에서 직접 대조할 수 있도록 개발자 전용 가이드를 제공합니다.

완료 상태는 다음 네 조건을 동시에 만족해야 합니다.

1. Description 문장이 원본과 문자 단위로 동일합니다.
2. Description의 일반 숫자와 화면 목적지의 붉은 원형 숫자가 슬라이드별로 대응합니다.
3. 목록·상세·등록·수정·모달·탭 등 한 HTML에 통합된 모든 설계 상태를 추적할 수 있습니다.
4. 개발자 가이드가 평상시 업무 화면과 출력 결과에 영향을 주지 않습니다.

## 2. 적용 범위

- 실행 HTML: 총 **50개**
  - 루트 `index.html`: 1개
  - `modules/` 아래 HTML: 49개
- 원본 화면설계: `docs/reference/`의 PPTX **12개**
- `SCREEN_LIST.md` 기준 작업 대상 설계 화면: **318개 슬라이드**
- 선행 기준 화면: `공통관리 > 관리자 관리` 1개 완료

리다이렉트 전용 화면, Description이 없는 슬라이드, 하나의 HTML에 여러 슬라이드가 통합된 화면은 조사 단계에서 별도 분류합니다. 원본이 없는 설명이나 목적지는 만들지 않습니다.

## 4. 구현 선행 작업

현재 기준 화면에만 있는 화면 전용 구현을 전 화면에서 재사용 가능한 공통 구조로 먼저 일반화합니다.

1. `#screenDescriptionModal` 같은 화면 전용 선택자를 역할 기반 공통 클래스와 데이터 속성으로 전환합니다.
2. `dashboard.js`에 `initDescriptionGuide()`를 추가합니다.
   - `D` 열기와 `×`·`Esc` 닫기
   - 열린 가이드 하나만 유지
   - 드로어 열림 상태와 목적지 번호 표시 동기화
   - 출력 모드 및 인쇄 시 강제 숨김
3. Description 데이터와 목적지 연결은 슬라이드·상태 식별자를 포함한 데이터 속성으로 관리합니다.
4. 숨겨진 탭·스텝·모달 목적지는 해당 UI가 열렸을 때만 표시합니다.
5. 기준 화면을 공통 컴포넌트 방식으로 다시 연결한 뒤 회귀 검사를 통과해야 다음 화면으로 확장합니다.

## 5. 화면별 작업 절차

각 HTML 파일마다 아래 순서를 반복합니다.

1. **원본 식별**: 메뉴명과 화면 제목으로 PPTX 및 관련 슬라이드를 확정합니다.
2. **원문 추출**: Description 텍스트 상자의 문단을 순서·공백·문장부호 그대로 추출합니다.
3. **번호 추출**: 붉은 반투명 원형의 숫자와 슬라이드 좌표를 수집합니다.
4. **상태 분류**: 기본 화면, 탭, 상세 모달, 등록/수정 모달, 확인 모달, 위저드 단계로 구분합니다.
5. **DOM 매핑**: 각 번호의 의미를 확인하고 실제 요소에 목적지 앵커를 연결합니다. 좌표 고정 배치는 사용하지 않습니다.
6. **Description 구성**: 화면 상태별 섹션을 만들고 일반 숫자 + 원문을 한 행씩 배치합니다.
7. **인터랙션 연결**: 드로어가 열린 동안 현재 보이는 상태의 목적지 번호를 표시합니다.
8. **자동 검증**: 원문·번호·ID·모달 대상·인라인 코드·CSS/JS 문법을 검사합니다.
9. **시각 검증**: 1920·1440·1280px에서 위치, 겹침, 잘림, 스크롤, 다크 드로어를 확인합니다.
10. **현황 기록**: 완료·원문 없음·목적지 불명확·설계와 구현 불일치를 매핑표에 기록합니다.

## 7. 검증 게이트

### 자동 검사

- PPTX 문단 수와 `.description-source-text` 수가 동일합니다.
- 각 문단의 Unicode 문자열과 길이가 모두 동일합니다.
- 슬라이드·상태별 Description 번호 집합과 목적지 번호 집합이 동일합니다.
- 목적지 앵커가 실제 DOM에 하나만 존재합니다.
- 중복 ID, 끊어진 `aria-labelledby`, 존재하지 않는 모달 대상이 없습니다.
- 인라인 `style`, 인라인 이벤트, 인라인 스크립트를 추가하지 않습니다.
- CSS 괄호와 JavaScript 문법 검사를 통과합니다.

### 시각·동작 검사

- `D`는 오른쪽 아래에서 업무 기능보다 낮은 시각적 우선순위를 가집니다.
- 드로어는 오른쪽에서 열리고 340px를 유지하며 내용은 상단 정렬됩니다.
- Description 번호는 일반 텍스트이고 목적지만 붉은 반투명 원형입니다.
- 번호가 입력값·버튼명·표 내용을 가리지 않으며 대상 요소를 따라갑니다.
- 상세 모달·탭·스텝을 열었을 때 해당 상태의 번호만 정확히 표시됩니다.
- `×`와 `Esc`가 동작하고 평상시에는 번호가 표시되지 않습니다.
- 인쇄·PDF·콘텐츠 출력 결과에 개발자 가이드가 포함되지 않습니다.

## 8. 예외 및 의사결정 규칙

- **Description 없음**: UI에는 빈 설명을 만들지 않고 현황표에 기록합니다.
- **번호만 있고 Description 없음 / Description만 있고 번호 없음**: 임의 추정하지 않고 검토 대상으로 분류합니다.
- **목적지가 구현 화면에 없음**: 기존 구현을 임의 변경하지 않고 `미구현 목적지`로 기록한 뒤 별도 승인 후 처리합니다.
- **여러 슬라이드가 하나의 DOM 요소를 가리킴**: 슬라이드·상태 키는 분리하되 같은 앵커를 재사용할 수 있습니다.
- **같은 번호 재사용**: 슬라이드 섹션이 다르면 허용하며 전역 고유 번호로 바꾸지 않습니다.
- **설계 오탈자**: 원문에는 그대로 유지하고, 필요하면 매핑표 비고에만 기록합니다.

## 9. 완료 정의

다음 조건을 모두 만족하면 전수 적용 완료로 판정합니다.

- 50개 실행 화면이 `완료`, `원문 없음`, `리다이렉트 전용` 중 하나로 빠짐없이 분류됩니다.
- Description이 있는 모든 설계 상태에서 원문 비교와 번호 대응 검사가 통과합니다.
- 목적지가 불명확하거나 미구현인 항목이 0건이거나, 사용자 승인된 예외 목록에 모두 기록됩니다.
- 전체 링크·모달·탭·기존 업무 인터랙션 회귀 검사가 통과합니다.
- 최종 적용 현황과 잔여 예외가 `docs/작업진행현황.md`에 반영됩니다.
