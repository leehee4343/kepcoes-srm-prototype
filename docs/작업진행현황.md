## 0. 원칙 (요약 — 상세는 작업지침서.md)
- 화면설계(PPTX)에 그려진 화면 구성·항목·문구·배치를 **추론하거나 임의로 바꾸지 않고 그대로** 재현한다.
- 시각 스타일(색상·폰트·여백·헤더/사이드바/버튼 등 공통 컴포넌트)은 `../DESIGN_GUIDE.md`를 그대로 따른다.
- 이 둘이 충돌하는 것처럼 보이면: **레이아웃/항목/문구 = 화면설계 그대로**, **색·타이포·공통 UI 부품의 생김새 = DESIGN_GUIDE** 라는 원칙으로 판단한다.
- **기능(업무 로직/유효성 검증/서버 연동)은 만들지 않는다. 화면과 화면을 실제 링크로 이어주는 것까지만 한다.** (탭 전환, 모달 열기/닫기 등 디자인을 보여주기 위한 수준의 인터랙션은 포함)
- 루트 `index.html`을 로그인 및 유일한 실행 진입점으로 사용하며, 이후 실제 화면 속 메뉴·버튼·행 클릭을 통해 화면과 화면을 탐색한다.
- **모든 업무 화면은 `modules` 아래 모듈별 폴더 안에 있다.** 폴더명은 PPTX 파일 번호와 1:1 대응하며, 공통 자산은 `assets`, 문서와 원본 자료는 `docs`에 분리한다.

- 점검 방법: 팝업 159개를 가이드 5.8(크기·구조·조회 모달·푸터)·5.2(검색 필터)·5.5(입력 폭) 기준으로 자동 점검하고, 설계 슬라이드와 문구 위치(화면 영역 / Description 칸)를 대조
- 조치
  - 검색+목록 팝업 18개 → 표준 필터 카드(라벨 폭 통일, `검색`·`초기화` 별도 줄) + 표준 목록 카드(`1 / N (총 N개)`, 10/20/50, 페이징) + `modal-xl`. 건수·조건 라벨(`서류 명칭`, `공통 심사/평가 명칭` 등)은 설계 슬라이드 기준, 비어 있던 마지막 열 제목(예: `매핑`) 복원
  - 7열 이상 표가 있는 팝업 10개 `modal-xl`, 행 `선택`·`매핑` 버튼 `.btn-task-register`, 계약담당자 매핑 팝업 하단의 잘못된 `계약담당자 매핑` 버튼 → `닫기`
  - 설계 Description 문구가 팝업 본문에 들어간 18건 삭제(예: "PMS의 수주계약 프로젝트를 호출합니다.", "[별첨1] … .xlsx", "메일/메시지가 발송되면 … 반드시 확인할 수 있어야 합니다."). 담당자 팝업에 붙어 있던 Description 번호 4는 설계 위치(목록의 기본 담당자 행)로 이동
  - 폭 지정 없이 좁게 줄어 안내 문구가 잘리던 입력칸 70개(41개 파일)에 내용 길이 기준 폭 지정(긴 입력 37·숫자 4·짧은 값 29)
  - CSS: 기간 버튼·날짜 줄바꿈 금지, 모달 안 카드 그림자 제거, 모달 안 목록은 긴 텍스트 칸만 줄바꿈해 모든 열 표시
